# Visual Presentation Studio

**A local-first engineering system for designing, building, rendering, inspecting, and validating high-quality AI-assisted presentations and visual narratives.**

**PT-BR:** Sistema local-first para projetar, construir, renderizar, inspecionar e validar apresentações e narrativas visuais de alta qualidade com workflows assistidos por IA.

[Versão em português](README.md)

## In 10 seconds

Visual Presentation Studio treats a presentation as a **visual engineering product**, not as a sequence of slides generated by a model.

It organizes the full lifecycle: thesis, narrative, visual direction, assets, implementation, real browser rendering, inspection, correction, and QA before a delivery can be considered final.

> **Core principle:** complexity may vary; production rigor does not.

## Why it exists

Presentation generators can produce something visually acceptable quickly, but that does not guarantee narrative coherence, layout quality, readability, responsive behavior, or consistency across versions.

The Studio exists to separate **generation** from **validation** and turn visual production into a reproducible, reviewable process.

## What makes it different

- a production lifecycle with **two explicit gates**;
- rendering and inspection of the real result, not just code validation;
- QA separated across content, narrative, visual, experience, and technical surfaces;
- support for 16:9 presentations, scrollytelling, exploratory experiences, and deliberate hybrids;
- local/downloadable delivery as a first-class output;
- sanitized public methodology and examples without exposing private deliverables.

## Lifecycle

```text
brief → proposal → Gate 1 → storyboard/specs → build → render/inspect/correct → QA → Gate 2 → FINAL → optional controlled learning
```

- **Gate 1:** freezes thesis, primary narrative, format, visual direction, primary interaction, stack, and destination before implementation.
- **Gate 2:** approves the exact finished build only after rendered inspection and no known BLOCKER or MAJOR issues remain.

## Current state

**Active development.** The current production route prioritizes **visual quality, reproducibility, and reviewability** over minimum latency or token cost.

A future research track may explore a faster draft route, but **Fast/Draft mode is not presented here as an existing capability**.

## Validation

From the repository root:

```bash
python -m unittest discover -s tests -v
python scripts/validate_repo.py
python scripts/public_safety_check.py .
cd templates/exploratory-react && npm install && npm run build
```

Automated success is necessary but not sufficient: final presentations still require **rendered visual inspection**.

## What is public here

This distribution is intentionally smaller and safer than the private laboratory. It contains reusable capability and generalized documentation, not confidential real presentations, raw project material, or private operational evidence.

Learnings from private work enter this repository only when they can be safely generalized and sanitized.

## Real-world application

The author's personal blog is one of the real environments used to apply and refine Studio principles — from narrative direction and visual composition to rendered QA. This demonstrates iterative use, not one-shot automatic generation of the whole site.

## Limits

This repository does not promise perfect instant generation, does not replace editorial/visual review, and does not publish the complete private laboratory.

See `SECURITY.md` and `AGENTS.md` before contributing.
