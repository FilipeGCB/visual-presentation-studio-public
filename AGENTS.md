# Public Repository Agent Instructions

This is the public distribution of Visual Presentation Studio. Treat every branch, commit, pull request, issue, review, Actions log/artifact, release, and attachment in this public repository as publicly visible.

## Non-negotiables

1. Never add private real-project source material to this public repository.
2. Public examples and fixtures must be intentionally public and rights-safe or **synthetic**.
3. Learning derived from private work must be newly generalized and **sanitized** before it enters this repository.
4. Never solve confidentiality risk with superficial renaming or light redaction.
5. Never commit passwords, tokens, cookies, API keys, SSH/private-key material, PEM/private keys, cloud/database credentials, credential-bearing URLs, or equivalent secrets.
6. Classify uncertain material as `UNKNOWN`. `SECRET` and `UNKNOWN` **fail closed**: do not commit or quote the material.
7. Do not paste possible secret values into issues, PRs, comments, logs, reports, or test output. Report only the class and safe path/location.
8. Preserve the Studio's Gate 1, Gate 2, rendered-inspection, and quality contracts when changing presentation behavior.

## Public promotion boundary

This public repository is a released capability surface, not the private learning laboratory.

Allowed public content includes reusable code, methodology, Skill resources, patterns, templates, QA rules, synthetic examples, and sanitized/generalized learnings that remain useful without a private source.

Do not commit private professional identities or data, private personal information, internal identifiers, real confidential slides/screenshots/assets, private datasets, raw prompts/transcripts, private URLs/endpoints, or attributable confidential logic.

When in doubt about provenance, rights, or sensitivity, stop. `UNKNOWN` fails closed.

## Verification

Before claiming readiness, run the repository tests, structural validator, public-safety scanner, and relevant starter build. A clean scanner is defense in depth; it does not replace semantic review.
